# ChatPort

**挑选对话，迁移到新账号，并确认它们已保存。**

[English](README.md) · [公开仓库](https://github.com/stors789/chatgpt-migrator)

ChatPort 通过 ChatGPT 分享链接和继续对话功能，把选中的对话复制到你的另一个**个人账号**。它在本机运行，无需 OpenAI API Key，也无需手动复制 Cookie 或登录令牌。

## 开始使用

安装 **Node.js 22 或更新版本**、**Google Chrome**。支持有桌面环境的 Windows、macOS 和 Linux。

```sh
git clone https://github.com/stors789/chatgpt-migrator.git
cd chatgpt-migrator
npm ci
npm start
```

打开 **http://127.0.0.1:4873**。

1. 点击打开原账号和新账号的浏览器窗口，分别登录两个不同的 ChatGPT 个人账号，均选择 **Personal／个人空间**。
2. 回到工具，点击「检查账号」，再「加载对话」。列表包括常规、归档和可访问的项目对话。
3. 按标题、日期、项目或迁移状态筛选。可以逐条预览、勾选，也可以选中整个筛选结果。切换筛选后，已选内容仍会保留。
4. 检查要追加的消息和间隔，确认你了解分享链接的可见范围，再点击「迁移已选对话」。
5. 迁移完成后查看凭证。如果显示「待检查」，点击「重新核验，不重复发送」。也可以粘贴在新账号中找到的 `https://chatgpt.com/c/...` 副本链接再核验。
6. 下载凭证。确认新账号的副本后，可自行到 ChatGPT「设置 → 数据控制 → 分享链接」撤销原账号的分享。工具不会删除原对话，也不会自动撤销链接。

项目中的对话会成为新账号里的普通对话；项目名称、指令、组织关系和项目文件不在本版本的迁移范围内。

使用期间保持终端打开。`Ctrl+C` 会等待当前操作结束，保留进度并关闭工具的浏览器窗口。再次执行 `npm start` 并连接相同账号，即可看到保存的凭证。

## 什么才算「已核验」？

分享前，工具记录当前分支上可见的用户和助手文本的摘要。接收时，会追加你填写的消息以及唯一的 `[ChatPort:…]` 标记。

只有以下条件全部成立，才会显示「已核验」：

- 新对话 ID 存在，并且不同于原对话 ID。
- 新账号的历史列表中确实存在该 ID。
- 再次读取时返回同一 ID，且对话可编辑。
- 完整的迁移标记消息已经保存，且仅出现一次。
- 标记之前的原有文本，在角色、顺序、内容和数量上全部与原始摘要一致。

工具会在操作过程中重新检查两个账号的身份。验证码、限流、错误账号、消息未保存、原文缺失或中途断开，都不会被标为成功。少量等待后的核验只会读取结果，不会重复发送消息。

「已核验」证明的是**当前分支的文本历史**，不保证图片、上传附件、生成文件、工具结果或其他历史分支仍可访问。包含媒体的对话会提示你另外检查。

## 中断与恢复

| 状态                             | 含义                         | 操作                             |
| -------------------------------- | ---------------------------- | -------------------------------- |
| 等待迁移                         | 尚未开始接收                 | 开始或继续                       |
| 生成分享链接／正在接收／正在核验 | 当前操作中                   | 等待，或请求完成当前对话后暂停   |
| 已核验                           | 副本已保存，原有文本核对通过 | 打开新账号里的副本               |
| 已停止                           | 在接收前失败                 | 处理错误后继续                   |
| 待检查                           | 接收过程可能已产生副本       | 查看凭证并重新核验，避免盲目重发 |

已核验的对话会跳过；待检查的对话不会自动重发。如果没找到迁移标记，请先查看新账号的浏览器。若副本在标记发送前已生成，需要先处理缺失的标记，才能通过核验。工具会保持待检查状态。

## 本机数据与隐私

- 默认数据目录为 `~/.chatport`，其中的浏览器资料包含登录会话，请保管好。
- 进度文件保存标题、分享链接、标记消息和校验凭证，不保存原始对话正文或复制出来的登录令牌。
- 界面只监听 `127.0.0.1`，拒绝外部来源和异常 Host 请求。
- 同一个数据目录只允许一个进程运行。强制终止后可能留下 `run.lock`；确认没有 ChatPort 进程运行后，才可删除该文件。
- 个人账号的分享链接对持有者可见。撤销链接不会删除已经被接收者保存的副本。[OpenAI 官方说明](https://help.openai.com/en/articles/7925741-sharing-conversations-and-scheduled-tasks-in-chatgpt)

可以设置 `CHATPORT_PORT`（默认 `4873`）、`CHATPORT_DATA_DIR`（默认 `~/.chatport`）和 `CHATPORT_BROWSER`（默认 `chrome`）。

需要使用随 Playwright 安装的 Chromium 时：

```sh
npm run browser:install
CHATPORT_BROWSER=chromium npm start
```

Windows PowerShell 使用 `$env:CHATPORT_BROWSER = "chromium"`，再运行 `npm start`。

## 使用边界

这是非官方网页集成；ChatGPT 的登录、列表和分享接口发生变化时，工具可能需要更新。仅支持个人账号，不迁移订阅、设置、记忆、GPT、项目文件，也不提供 Business／Enterprise／Edu 跨空间迁移。

遇到登录验证或验证码，请自行在浏览器完成；工具不会解决验证码，也不使用隐身插件。遇到限流，先暂停等待，再增加间隔。不要并行运行迁移。

列表格式改变会直接报错，不会把不完整的结果当作全量列表。新 URL、输入框或页面上的共享说明，都不能代替保存结果的核验。

## 开发与测试

```sh
npm run check
npm test
npm run browser:install
npm run test:e2e
```

自动测试使用虚构账号、对话和网页接口，覆盖筛选、预览、分享、发送、校验、误报、中断恢复、账号切换和本机 HTTP 边界。**这些测试不登录真实 ChatGPT 账号**；真实账号兼容性需要另行做少量人工试迁移，不能把测试通过当成对未来接口的保证。

提 Issue 时请提供发生错误的步骤和错误文字。不要提交 Cookie、令牌、浏览器资料、真实对话正文或未脱敏的迁移凭证。
